# A股全景看板 · 使用说明

> 这份文档同时随程序发布，打包时会复制成发布目录里的 `README.md`。
> 仓库首页看 [../README.md](../README.md)。
>
> 文中的 `C:\ds\...` 是作者本机的路径，你按自己解压的位置替换即可。

一个**不依赖浏览器**的 A 股行情软件。双击打开就是 Windows 原生窗口，
不启动本地服务、不占端口、不需要在浏览器地址栏里敲 `127.0.0.1`。

界面全部中文，数据来自公开接口，红涨绿跌，符合国内看盘习惯。

## 一、三步跑起来

> 只想用、不想装 Python？到 `C:\ds\A股全景看板桌面版_软件版\` 双击 `A股全景看板.exe` 就行，
> 那是打好的独立程序，目标机器什么都不用装。下面这三步是给改代码的人看的。

### 第一步：装依赖

打开命令行，进到本目录，执行：

```bat
python -m pip install -r requirements.txt
```

只需要七个库：PySide6、pandas、numpy、akshare、requests、openpyxl、XlsxWriter。

### 第二步：确认离线板块库在

本目录下应该有一个 `数据` 文件夹，里面是十几个 `板块_*.json`。
这些是板块成分股的离线库，没有它，「板块全景」下钻会没有数据。

如果 `数据` 文件夹是空的（或者想让库更新到最新交易日），执行一次建库：

```bat
python build_sector.py
```

大约 10~15 分钟，可以中途 Ctrl+C 再重跑，已完成的板块会跳过。

### 第三步：双击运行

双击 `运行.py`。

或者用命令行：

```bat
python 运行.py
```

窗口会在两三秒内出现。没有浏览器、没有端口、没有进度条刷屏。

## 三、界面上的几个开关

**退出**：窗口右上角有一个 ✕。点它会先问一句「确定要退出吗」，默认按钮是「继续使用」，
按 Esc 也是继续使用，所以手滑点错不会直接关掉。点「退出」才真的退出。
点标题栏那个系统关闭按钮、按 Alt+F4，走的是同一个确认框。

这个确认框不是系统自带的弹窗，是自己画的（`应用/组件/退出框.py`）：428 宽、12 圆角、
白底带 1 像素描边、外面一圈透明，跟软件里其它卡片同一套圆角和留白；标题 18 号粗体、
正文 13 号、补充一句小字 12 号；下面一条 1 像素分隔线，再往右排「退出」（红色描边）和
「继续使用」（深色实心，默认按钮）。出现时有 130 毫秒淡入，按住它拖能挪位置。
深色主题下白底会变成深灰底、字自动变浅，对比度最低也有 5.15（规范要求 4.5）。

**刷新**：右上角 ✕ 左边有一个「刷新」按钮，点一下把**打开过的页面**全部重取一遍。

它做的事有三件：清掉 `data_fetcher` 的内存缓存、让每个页面重放自己上一次的取数参数、
顺手把左侧栏底的交易状态也更新一次。为什么要清缓存：实时快照的缓存期是 60 秒，
不清的话点完刷新拿回来的还是刚才那份，看着像没反应。

只有建过的页面参与刷新。十个模块是懒加载的，没点开过的页面连控件都还没有，
自然也就不用取数 —— 这也意味着「刷新」不会偷偷把十个模块的接口全打一遍。

同一份数据不会取两遍：页面里的表、折线、柱状、指标卡都带一个 `重取`，
`页面基.刷新()` 把它们扫一遍；外层区块如果自己也挂了 `重取`，里面的子块就跳过。
各页私有的那几次取数（首页的指数/全市场、板块页的列表/热力、个股页的查询、
期货页的主力合约）由子类覆盖 `刷新()`，先调 `super().刷新()` 再补上。

**参数是重放的，不是重置的**。涨停股池停在 10 月 31 日，刷新之后还停在 10 月 31 日；
板块页选中了某个板块，刷新会把那个板块的成分股和 K 线一起重取，而不是退回默认页面。

点下去按钮会变成「刷新中…」并置灰，等后台队列跑完再变「已刷新」，1.4 秒后恢复成「刷新」。
鼠标停在按钮上能看到「上次刷新 17:48，共发出 4 次取数」。后台是单线程排队
（`py_mini_racer` 不是线程安全的），页面开得多的时候要等一会儿，最长等 120 秒，
超时就显示「刷新超时」，不会一直卡在「刷新中…」。

等多久算正常，实测一次：只开着首页点刷新，按钮「刷新中…」停了 12.1 秒才变「已刷新」。
拖后腿的是全市场快照那一笔（五千多只票的实时价）。这是排队等回来的，不是按钮没响应 ——
所以宁可让它一直灰着，也不提前把按钮点亮假装刷完了。

事件日历那张业绩预告表带关键字筛选，重取回来的是全量数据，
所以表刷新完会自己把关键字再套一遍，不会出现「输入框里还有字、表里却冒出没筛过的行」。

**主题**：左侧那排按钮，共四个状态。

- 浅色 / 深色：固定一种。
- 跟随系统：Windows 切到深色模式，软件立刻跟着变。
- 随时间变化：早上 7 点前和晚上 19 点后自动切深色。

这个选择会记住，下次打开还是上次那个。

**导出**：每张表格右下角都有「导出本表」，可以存成 CSV 或 Excel。
CSV 用 UTF-8-SIG 编码，用 Excel 直接打开不会乱码。

**复制表格里的文字**：表格里的每一格都能复制出去 —— 比如业绩预告表的「预测指标」和
「业绩变动」，那两列字很长，以前只能截图，现在直接选中就能粘到别处。

- 选中一格或多格（按住鼠标拖一片），按 `Ctrl+C` 就复制。
- 点右键还有更细的：只复制这一格 / 复制这一整行 / 复制这一整列 /
  复制整张表（带表头或不带）/ 全选。
- 复制出去的是**界面上看到的那份文字**，用制表符分列、换行分行，粘进 Excel、WPS、
  QQ 聊天框都对得齐；长句不会截断（「业绩变动」那 100 多字也是全的）。
- 表头也能单独复制：选中表头所在行不可行，用右键的「复制整张表（带表头）」。
- 复制完左下角的「共 N 行」会临时变成「已复制 X 个字符」两秒，让你确认真的复制上了。

**双击下钻**：板块全景里的板块列表，双击某一行就展开它的成分股。

**板块体系与行业层级**：板块全景顶部三个按钮就是三套体系 —— 行业板块、概念板块、地域板块。
选行业板块时，下面会多出一排「行业层级」按钮：一级行业（31 个）、二级行业（129 个）、
三级行业（332 个），点哪个就换哪个层面看，**热力图和板块列表同时跟着换**。
层级切换后上面板板块列表的行数就是该层的板块数，不再是三层混在一起的 492 行。

切到概念板块或地域板块时，「行业层级」那一排会自动收起来 —— 概念和地域没有层级之分。
三套体系的成分股互不重叠：行业是申万口径，一只股票只属于一个行业；
概念是新浪口径，一只股票可以挂在好几个概念下；地域按注册省份。
所以看行业板块的涨跌家数加起来等于全市场，看概念板块则会重复计数，这是口径本身决定的。

实现上，层级这一维贯穿三层：`fetch_sector.行业层级` 把「一级行业 / 二级行业 / 三级行业」
映射到离线库里的「申万一级 / 申万二级 / 申万三级」分类，`板块列表()` 与 `板块涨跌一览()`
都多了一个 `层级` 参数，缓存键也带上层级（`行业板块|三级行业`），
否则一级和三级会互相覆盖，切回去看到的还是上次那层。

**热力图怎么看**：板块全景最上面那块。方块面积按成交额（开了 0.8 次方压缩，
所以不是严格成比例），颜色按涨跌幅，浅色是涨跌接近零，越红涨得越多、越绿跌得越多，
±5% 封顶。鼠标停上去浮出「成分多少只、上涨几家、下跌几家」，
单击方块直接加载这个板块的成分股 —— 和双击下面的列表是同一个效果。
方块按三层口径切换：行业板块跟着上面选的「行业层级」走（默认申万二级），
概念板块用新浪概念板块、地域板块用省份，三者互不重叠，所以分类之间不会重复计数。

**右侧色标**：热力图右边那条竖着的渐变就是颜色图例，从下往上依次是
−5%、−2.5%、0%、+2.5%、+5%，刻度画在条的右边，零的位置有一道细分隔线。
条本身用和方块完全相同的混色公式算出来，所以看到某个方块的颜色，
横着移到色标上就能估出它大概涨跌几个点，不用记公式。

**放大 / 收起**：三个入口 —— 分区标题右边的「放大」按钮、双击热力图任意位置、
或者再点一次按钮 / 再双击一次收起。放大时下面三块（板块列表、成分股）
会被藏起来，热力图铺满整页高度；高度变化不是瞬间跳，
而是让每个方块从旧位置平滑长到新位置（300 毫秒，先快后慢），
块多的时候能明显看出「从中间散开」的过程。
实现见 `应用/组件/热力图.py` 的 `过渡到高度()`：它先按新高度算一遍终点，
再按板块名称把旧块和新块配对做插值 —— 只靠 `resizeEvent` 不行，
因为它要等一轮事件循环，那时旧位置已经没了。

**全局总览页也能放大**：同一套操作（按钮 / 双击 / 再点一次收起），
只是那里放大时要藏起来的是下方的「指数明细」表，而板块全景页藏的是
板块列表、成分股和板块 K 线。两页各管各的状态，互不影响。

**表格列宽**：每张表按内容真实测量列宽（不是估算），装得下就撑满面板，
装不下就出横向滚动条，绝不会把前面几列压成窄条。
像「业绩变动」「业绩变动原因」这种一百多字的长文本列，宽度封顶，
鼠标停在格子上看完整内容。

**鼠标悬停提示**：导航栏每个按钮上停一下，会浮出一行说明。这一行也必须是中文，
不许出现 PE/PB、PMI、CPI、ETF 这类缩写 —— 中文界面上突然蹦英文很突兀。
同理，表格右下角导出按钮的提示写的是「把当前表格存成表格文件」，
保存对话框的筛选写的是「逗号分隔表格 / 电子表格」，不写 CSV、Excel。
改文案时请守住这条，`工具/_查提示.py` 会扫出所有带英文字母的悬浮提示。

**涨跌分布怎么看**：全局总览中间那张柱子图，把全部 A 股按当日涨跌幅分成 13 档，
从左到右是跌停、−9.8~−7、…、平盘、…、7~9.8、涨停，柱高是落在这一档的家数。
左侧六档用绿色系、右边六档用红色系，越靠外颜色越深，平盘那根是灰的。
两头翘说明两极分化，中间高说明大部分股票在小幅波动。
分档边界见 `应用/页面/overview.py` 的 `档名` 与 `_分档()`，改档位只要动这两个地方。

**PMI 折线**：宏观数据第一页，最近五年 60 个月的制造业与非制造业两条线，
虚线是 50 荣枯线。取数用 `fetch_macro.PMI()`，日期从「2026年09月份」这种中文月份里
扒出年月再补成当月 1 号 —— 直接 `pd.to_datetime` 认不出来。

**宏观四个子页都有图**：

| 子页 | 图 | 数据 |
|---|---|---|
| PMI 景气 | 制造业 / 非制造业两条折线 + 50 荣枯线虚线 | 225 个月 |
| CPI 与 PPI | 两张同比折线，各带 0 轴虚线 | CPI 225 / PPI 249 |
| 货币与社融 | M2、M1 同比两条折线（剪差就是剪刀差）+ 社融单月增量柱状 | 225 / 136 |
| 国债收益率 | 10 年、2 年、期限利差三条折线 + **收益率曲线** | 798 个交易日 |

**国债收益率曲线**：宏观数据最后一页第二块。横轴是期限（2 年 / 5 年 / 10 年 / 30 年），
纵轴是那一天的到期收益率，三个系列叠在一起：最新一天（红）、一个月前（蓝）、
一年前（灰）。一眼能看出曲线是**整体上移**（资金变贵）还是**变陡 / 走平**。
下方一行字会直接给出判断：「曲线 陡峭向上，长端要求更高的补偿（2 年 1.25% → 10 年 1.65%，
相差 +0.40 个百分点）」，倒挂时会明确写「倒挂」。

注意曲线和上面那张「收益率时间序列」是两回事：上面那张横轴是日期，看单只期限的历史走势；
这张横轴是期限，看同一天不同期限之间的相对关系。两者都要，缺一个就少一半信息。

**板块市盈率排行**：估值水平第一页顶部，13 个重点板块的滚动市盈率横着排队，
最贵的排在最上面。柱子用中性的蓝色，因为估值不是涨跌，用红绿会让人误会方向。

**个股 K 线的四张图**：个股微观一页里，从上到下是蜡烛图（叠均线）、
成交量柱（颜色跟当天涨跌一致）、MACD（红绿柱 + DIF / DEA 两条线），
勾上 KDJ 之后最下面再多一张 K / D / J。

口径跟网页版（`C:\ds\A股全景看板\charts.py`）逐条对齐，不是另起一套：

| 项目 | 桌面版 | 网页版 |
|---|---|---|
| MA 颜色 | MA5 `#d18700` 橙 / MA10 `#2f6fd0` 蓝 / MA20 `#9b59b6` 紫 / MA60 `#0f766e` 青 | 同左 |
| MA 候选窗口 | 5 / 10 / 20 / 60，界面上可任意勾选 | `config.均线候选` |
| MACD 参数 | 12 / 26 / 9，柱 = `(DIF − DEA) × 2` | 同左 |
| MACD 线色 | DIF 橙 `#d18700`，DEA 蓝 `#2f6fd0` | 同左 |
| KDJ 参数 | 9 / 3 / 3，RSV 用 9 日最高最低，K、D 用 `ewm(alpha=1/3, adjust=False)`，J = `3K − 2D` | 同左 |
| KDJ 线色 | K 橙 `#d18700`、D 蓝 `#2f6fd0`、J 紫 `#9b59b6` | 同左 |
| 悬停 | 停在哪根就显示「日期（分钟线再带时间段） 阳线/阴线 +x.xx% / 开 高 / 低 收 / 量」 | 日期 + 同样四项（Plotly hovertext） |
| 涨跌配色 | 红涨绿跌，和国内软件习惯一致 | 同左 |

MACD 参数固定 12/26/9，和通达信、同花顺的默认口径一致，重画时用 pandas 的
`ewm(adjust=False)` 算，和手算逐值对得上（误差 0）；KDJ 也是逐值对，最大差 `0.00e+00`。

界面上方一排勾选框可以随时改：四个均线窗口随便勾（**不允许全部取消**，至少留一条，
否则图上什么都不画，看起来像坏了），MACD 默认开、KDJ 默认关。

**K 线怎么看远近**：三张图是联动的，鼠标在哪张图上滚都一样。

| 操作 | 效果 |
|---|---|
| 向上滚滚轮 | 放大，以鼠标位置为中心，最少放到 15 根 |
| 向下滚滚轮 | 缩小，最多缩到全部历史 |
| 按住左键左右拖 | 平移，光标变成抓手，往左拖看更晚的数据 |
| 双击 | 复位到最近 300 根 |

图下方有一条提示，随时写着「当前显示第几根到第几根」。默认只显示最近 300 根，
但**数据是一次全量灌进图里再改显示区间**，所以拖动时不会一根一根重新取数
（实测一次缩放 9 毫秒，能到 100 帧以上）。均线、MACD 也都是拿全量数据算完再截取的，
随便拖到哪一段，指标开头都是整的，不会从半截开始。

**分钟 K 线到底停在哪一分钟**：分钟周期的横轴是 0 … N-1 的数值轴，位置本身不说话，
所以悬停时直接写这根覆盖的区间，例如 `2026-11-06 10:57–10:58`；底部那条提示也
跟着显示到分钟（`13:57 至 15:00`）。

区间不是猜的，是 `[标签 − 粒度, 标签]`，依据是新浪的口径：每根 K 线标在这根的
**结束**时刻上，1 分钟线一天 240 根、首根 09:31、末根 15:00（2026-11-06 实测 238 根，
缺的两根是那一分钟没有成交，接口直接不给），5 分钟线首根 09:35、末根 15:00。
跨午休时把起点夹到 13:00，否则 13:01 那根会被算成从 11:30 起。

日线以上不加时间段：日期本身就是一个交易日，周线和月线的标签分别是那一周、那个月，
换算成区间只是重复一遍。`_验悬停时间段.py` 用真数据把开盘首根、上午收盘、午休后
首根、收盘末根四处的区间逐条钉住，27 项断言全过。

**读数卡为什么不用 QToolTip**：一开始用的就是 `QToolTip.showText()`，离屏断言全过，
可拿到真实桌面上扫 210 个点会漏三处，而且这三点都不是偶发：①提示框盖住光标时会触发
视口的 `leaveEvent`，而 `leaveEvent` 里要 `hideText()`，等于自己把自己关掉；②Qt 每次
换文本都重建那个顶层提示窗，重建的那一帧采到的就是「不可见」；③提示框是独立顶层窗口，
靠近图边时会飘到图外面去。所以改成挂在 K 线图里的一个 `QLabel` 子控件：坐标自己算，
默认在光标右侧 16 像素，右边放不下就翻到左侧，上下夹在图内，`WA_TransparentForMouseEvents`
让鼠标事件直接穿过去，缩放、拖动、复位、换数据、切主题时主动收起来。真屏复测 210/210
全部弹出，卡片 174×98 逻辑像素，整块都在图里，也不挡光标（`_验悬停真屏.py`，13 项）。

卡片里的成交量按周期换单位：日线一天几千万股，写「0.05 亿」；一分钟只有几万股，
同一个除数会把整行写成「0.00 亿」，所以分钟周期改成「22.6 万股」。数据源给的
本来就是股（新浪日线和分钟线都是），换的只是说法，没有换算比例上的猜测。

**分钟线的时间轴**：切到 60/30/15/5/1 分钟时，横轴刻度会自己从「2026-10-30」
变成「10-30 15:00」这种带时刻的写法（可见跨度不超过 60 根时只写「15:00」）。
数据源给分钟行情的「日期」列全都是同一天，真正有用的是「时间戳」列，
所以 `应用/组件/K线图.py` 的 `_规整()` 里有这一句：只要表里出现「时间戳」，
就把它当成横轴的时间。另外「日期」和「时间」两列都会被映射成同一个内部列名，
重命名会产生重名列，所以映射时用 `已用` 集合做了去重。

**复权与回看**：个股微观页顶部的「复权」有三种（不复权 / 前复权 / 后复权），
「回看」有五档（1 年 / 2 年 / 3 年 / 5 年 / 全部），改了立刻重取。
切到分钟周期时「回看」会自动变灰 —— 分钟接口给多少就是多少（新浪固定最近 1970 根），
传日期也没用，不如干脆不让点。

**资金面的图**：个股与概念资金流各有一张「净流入前 20 名」横条（单位亿元，
正数红、负数绿），下面是对应的明细表；两融页是沪市融资余额与全市场融资/融券余额两条折线。
北向那一页**故意只给表**：2024 年 8 月之后官方停止披露日度净成交额，
近期这一列全是空值，硬画只会得到一条空白折线。

**事件日历的筛选**：业绩预告可以换报告期（默认自动取最近一期）、
在「关键字」框里打「半导体」这类词会当场把表格筛掉，**不会重新联网** ——
它筛的是已经拿到手的 531 行原始数据（`可刷新表格.原始`），所以打字是即时的。
预约披露可以换市场（沪深/沪市/深市/科创板/创业板/京市），限售解禁可以换时间区间。

**自选可以一次贴多只**：输入框里用空格、逗号、分号、顿号隔开都行，
例如 `600519 000858，002594、300059`，一次最多加 20 只。加完下面那张柱状图
会按涨跌幅重画，说明里写着「最强 / 最弱」分别是哪只、多少点。
自选池存在 `数据\自选池.json`，换电脑把它带过去就还在。

**加载时转圈**：网络慢的时候，提示行左边会有一个小圈在转，数据回来自己停，
不用盯着空白页面猜是不是卡了。这不是给每个页面单独接的动画 —— 而是那一行
「数据来源」本身换成了会转的控件（`应用/组件/加载圈.py` 的 `加载提示`），
判据是文字里有没有「正在」「加载」：

| 什么时候 | 提示文字 | 圈转不转 |
|---|---|---|
| 刚点开、还没取到数 | `正在取数…` | 转 |
| 数据到了 | `数据来源：新浪 ｜ 12 行` | 停 |
| 接口挂了 | `取数失败：…` | 停 |
| 空白图表占位 | `暂无数据` | 停 |

所以只要某处调了 `setText("正在取数…")`，圈就自动出现，改成正常文字就自动停，
一个地方都不用额外写。转的时候 16 毫秒一帧、大约每秒 0.9 圈，
弧长 100°，用锥形渐变从实色褪到尾部的透明，所以看起来是一道淡出的尾巴而不是硬块。
控件一隐藏（`hideEvent`）就停表，藏起来的圈不烧 CPU。

**表格正中央也会转圈**：提示行那个小圈只有 14 像素，盯着一张空表看容易以为界面死了。
所以数据表自己带一层遮罩（`应用/组件/数据表.py` 的 `表格加载层`），
取数期间在**表格正中间**摆一个 28 像素的圈 + 一行「正在获取数据…」，
背景用不透明的卡片色把空表头、「暂无数据」一起盖住 —— 用户看到的就是一个干净方框里有一圈在转。

```python
表.置加载(True, "正在获取板块列表…")   # 开始取数
表.换数据(框)                          # 数据到了，换数据会顺手收掉遮罩，不用成对调用
表.置加载(False)                       # 只有失败分支才需要手动收
```

三层兜底保证不会出现「圈一直转」：`换数据()` 无条件收遮罩（哪怕来的是空表）、
每个页面的失败回调都显式调一次 `置加载(False)`、遮罩跟着表格 `resizeEvent` 重算几何，
所以拉窗口、切全屏、展开热力图都不会让圈跑偏。实测遮罩与表格视图**尺寸完全相等（偏差 0,0）**。

**居中的基准是数据区，不是整张表**：遮罩盖的是整个 `QTableView`（含 36 像素高的表头），
但人眼找的是被表头挤下去的那块**数据区**的中心。所以定位一律取
`视图.viewport().geometry()`。
文字高度用 `QFontMetrics.boundingRect(..., TextWordWrap)` 算，而不是 `QLabel.sizeHint()`
（样式表给的行高比字形高一截，按 sizeHint 摆整块会往上飘几像素）。
实测 1440×920 下横向偏差 0；窗口缩到 560×400 或放到 1280×860 都一致。
滚动条出现/消失会改 `viewport` 几何，所以还装了 `eventFilter` 盯它的 `Resize`。

**居中对象是「圈」，不是「圈加文字」**：这一条改过两次。第一版按「圈 + 间距 + 一行字」
这一整块居中，看着应该有道理，实测却发现**圈比数据区中心高 12 像素** ——
文字在圈下面把整块中心往下拉，圈就永远偏上。十个模块逐表量出来都是 `-12`：
overview 圈心 112 / 数据区中心 124，sectors 127/139，capital 197/209，events 237/249……
现在改成让**圈自己的圆心压住数据区中心**，文字挂在圈下方；
复量十个模块的 9 张表，圈心偏差全部是 `(-1, -1)`（半个像素的取整误差），
文字落在圈下方 10 像素处。窗口很矮时才会把整块往上收，避免文字跑出遮罩。

**遮罩宽度要跟着表格走**：这一条也踩过一次。`置加载()` 往往在表格刚被 new 出来、
还没参与布局的时候调用，那会儿 `QTableView` 只有 100 像素宽；把当时的 `rect()` 记下来，
遮罩就一直是一条窄带，中心算出来贴在表格最左边（实测偏差 −490 像素）。
现在三处兜底：`转起来()` 先按父控件当前尺寸重新贴一次、`showEvent` 里贴一次
（子页被切出来时才拿到真实尺寸）、`paintEvent` 里再兜一次（滚动进可视区时补齐）。
复量十张表，横向偏差全部 `-7` 像素以内（−7 是滚动条那一列造成的半中心差）。

**图表类面板的转圈也居中**：个股微观、衍生品、宏观的图表块里只有一行提示文字，
原来那个圈贴着面板最左边转（偏差 −564 像素），看着像跑到页面外面去了。
现在 `加载提示` 在转圈状态下用两个弹簧把「圈 + 文字」推到这一行的正中间，
停下来之后文字照旧左对齐 —— 空闲状态的样子和以前完全一样（实测 3 个页面 6 条
非转动提示，被居中的 0 条）。

**折线图能读数、能放大**：宏观数据里的六张折线（PMI、CPI、PPI、M2/M1、国债收益率、
国债收益率曲线）和估值页的两张（市盈率、市净率/市销率）都支持下面两件事：

| 操作 | 效果 |
|---|---|
| 鼠标在图上移动 | 出现一条竖虚线定位到最近的月份/交易日，鼠标旁边弹出读数：第一行是日期，下面每行一条线（系列名 + 数值） |
| 点右上角「放大」或双击图 | 这张图铺满整页，其它内容临时收起来，再点一次「还原」回到原样 |
| 鼠标移出图外 | 竖虚线与读数一起消失，不会留在图上 |

放大时长高的动画是 300 毫秒（收回 260 毫秒），缓动是 OutCubic，
放大后横轴不会变密 —— 还是同一个类别轴，只是每个点之间拉开，读数点也一样准。

柱状图（社融、行业估值排行、资金流排行、自选涨跌、全市场分布）同样能放大，
柱子上本来就印着数值，所以不需要悬停读数。

**整列都是空的列，直接不显示**：有些列在数据源那头就是空的，不是取错了 ——
北向资金的「当日成交净买额」自 2024-08 起停止日度披露、龙虎榜的「上榜后10日」
对最近几天必然为空、新浪快照不提供「市盈率/市净率」时对应列也是空的。
这些列留在表里就是一片空白格，用户第一反应是「这里没显示出来」。
所以 `数据表.换数据()` 会先过一遍 `_去掉空列()`：`None / NaN / 空串 / "-" / "—"` 都算空，
整列没有一个有效值就把这一列拿掉，并在表格底部写「已隐藏 N 个空列」；
但至少保留 3 列，免得删到只剩一列反而没法看。导出的是你看到的这份，不含被隐藏的空列。

**图例里不出现「看不见的系列」**：QtCharts 给每个 `addSeries` 的系列都建一个图例标记，
哪怕这个系列是隐藏的。折线图为了做悬停读数加了一条隐藏的十字虚线，
不收拾它，图例右边就会多出一个**没有文字的小色块**，看着像图画残了。
所以 `折线图._同步图例()` 每次重画都把隐藏系列的标记一并隐藏，十字线的标记则永久隐藏；
`K 线图` 的 MACD 柱子同理（两个 `QBarSet` 会各占一个同名标记，藏掉只留 DIF / DEA）。

## 五、几个实现上的取舍

**界面为什么长这样：一套写死在 `应用/主题.py` 里的设计令牌**
这些数字不是随手调的，是按公开的设计规范挑的，改界面只需要动
`应用/主题.py` 顶部的两个字典（`浅色` / `深色`）和 `模板` 那段 QSS：

| 项目 | 取值 | 依据 |
| --- | --- | --- |
| 字号 | 只有 11 / 12 / 13 / 18 / 22 五档 | Ant Design 字阶建议控制在 3~5 种；NN/g 建议尺寸不超过 3 档 |
| 颜色档位 | 正文、次要、弱化三档 | Ant Design 用透明度阶梯表达层级，企业产品颜色要克制 |
| 对比度 | 全部 ≥ 4.5:1，实测最低 4.80 | W3C WCAG 2.1 AA（正文 4.5:1，且比值不可四舍五入） |
| 间距 | 只用 4 / 8 / 12 / 16 / 24 | Ant Design 8 基数栅格，4 作半档 |
| 表格 | 行高 28，单元格内边距 4×12，无竖线，只留浅色横线 | Ant Design 数据展示：表格最清晰，视觉噪音要低 |
| 侧栏 | 固定 232 宽，导航项 36 高，主题按钮 2×2 每个 30 高 | 左导航固定宽 + 右自适应 |
| 主色 | 只有涨红跌绿是彩色，界面本身近乎无彩色 | 颜色只用来表达数据含义 |

浅色是默认且是调优重点：NN/g 的实测结论是正常视力下浅色表现更好，
而且字号越小浅色的优势越明显；深色主要给弱光环境和省电用。

想自己改观感，记住两条就够：① 字号别随便加第六档，一加层级就散了；
② 任何新颜色都要先过一遍对比度（4.5:1），尤其是 11px 的小字。

三个体检脚本放在 `C:\ds\打包桌面\工具\`：`_审视觉.py`（字号档数、16 组对比度、
颜色档位、QSS 间距是否落栅格）、`_审布局.py`（代码里所有边距/间距是否落 4 栅格）、
`_查错位.py`（3 种窗口尺寸 × 10 个模块，逐控件量文字有没有被裁、控件有没有重叠）。
改完界面跑一遍，全绿再打包。

**表格里的字为什么复制不出去，得自己写？**
`QTableView` 只负责显示，剪贴板里什么都没有 —— 不接就真的按 `Ctrl+C` 没反应。
实现分两层：`数据表` 上挂一个 `QShortcut(QKeySequence.Copy)` 接 `Ctrl+C`，
右键菜单再给「只复制这一格 / 整行 / 整列 / 整表」；取文字走模型的
`单元格文本(行, 列)`，拿的是**格式化之后**的文本（界面上写「1.23 亿」，复制出去的
也是「1.23 亿」，不是 `123456789.0`），用 `\t` 分列、`\n` 分行，粘进 Excel 才落格。
两个坑：一是选中项是代理模型的下标，必须先 `mapToSource` 才能取到原始行列；二是
`setSortingEnabled(True)` 会让 Qt 立刻按第 0 列排一遍、而且默认是**降序**（序号变成
倒着显示），所以建表时要显式 `sortByColumn(-1, ...)` 清掉初始排序。

**退出按钮为什么不浮在内容上？**
浮在右上角会盖住指标卡最右边那一个。所以内容区顶上单独留了一条 40 像素的窄条，
✕ 放在窄条右端，页面内容整个在窄条下面。代价是内容区的可用高度少 40 像素，
所以页面自身的上边距从 20 调到了 12 抵回来。

**退出确认框为什么不用系统消息框？**
系统消息框是方角、灰底、默认字号，放在这套界面里像个外来窗口。自己画一个只有两个
代价要注意：一是圆角必须用 `QPainterPath` 填，靠样式表的 `border-radius` 只切背景、
四个角还是方的；二是全局样式里有 `QWidget { background: @底色 }`，卡片里的每个标签
都得显式写 `background: transparent`，否则白卡片上会出现一块块页面底色的方块
（实测抓图中心色读到 `#fbfbfc` 而不是 `#ffffff`，就是这条漏了）。

**为什么退出时用 `os._exit(0)` 直接杀掉进程？**
如果还有后台线程卡在网络请求里，正常退出会去析构 `py_mini_racer`，
那个库在多线程下析构会 FATAL 崩掉，Windows 就会弹一个「程序已停止工作」。
用户明明是自己点的退出，却看到崩溃提示，没法解释。所以先给后台 2.5 秒收尾，
然后跳过所有清理直接硬退。

**对话框按钮为什么是中文的？**
Qt 自带的对话框（消息框的确定/取消、保存文件框的保存/打开）默认是英文。
`main.py` 的 `_装中文翻译` 会把 `PySide6/translations/qtbase_zh_CN.qm` 装上，
这些按钮就变中文了。打包时要在 spec 的 `datas` 里显式带上翻译包，
否则 exe 里又会退回英文（PyInstaller 默认不收这个目录）。

**为什么取数只能单线程？**
akshare 底层的 `py_mini_racer` 不是线程安全的。两个线程同时调，
进程会直接 `[FATAL:partition_address_space.cc(243)] Check failed` 崩掉，
不是抛异常，是整进程消失。所以 `应用/后台任务.py` 把线程池锁死在 1。
代价是同时只能拉一个接口，好处是绝不崩。

**为什么还要把线程池的过期时间设成 -1？**
只锁 `setMaxThreadCount(1)` 还不够。`QThreadPool` 默认工作线程 30 秒没活就销毁，
下一个任务会**换一个新线程**跑。`py_mini_racer` 的 V8 分区分配器在一个进程里
只允许初始化一次，换线程重新初始化照样 FATAL。所以 `线程池()` 里还有一句
`池.setExpiryTimeout(-1)`，让那个工作线程一直活着。代价是常驻一个空闲线程。

**判断「后台还有没有活」为什么不能只看 activeThreadCount？**
任务刚 `start()` 提交、线程还没被唤醒的那一瞬间，`activeThreadCount()` 是 0。
用它判空闲会让自动化测试在数据还没到的时候就开始量行数，量出「0 行」的假 bug。
所以 `后台运行()` 自己加一个待办计数 `_在跑`，`空闲()` 要它归零**并且**
线程池也空才算闲。

**为什么柱状图 / 折线图各写一个组件，而不是一个组件加个开关？**
两种图要处理的细节完全不一样：柱状图要按正负配色、要能逐柱单独上色
（涨跌分布和自选涨跌用得上）、横向时类别轴是自下往上的（所以标签和数值都要倒序）；
折线图要画多条线、要支持一条虚线参考线（荣枯线、零轴）、
还要处理缺值（`None` 会被断开而不是连到 0）。合在一起全是 `if 横向` 这种分支，
不如拆成 `应用/组件/柱状图.py` 与 `应用/组件/折线图.py` 两个小文件。

**为什么翻到某页才拉数据？**
全部预加载的话，一开软件就要打几十个接口，首屏要等一分钟以上。
现在点哪个模块才建哪个页面，其余模块连控件都不存在。

**为什么分钟线只有 1970 根？**
这是新浪接口的硬限制，不是我们截断的。想做长周期分钟复盘，
需要每天收盘后把当天数据落盘累积，这是下一阶段的事。

**为什么板块成分股用离线库？**
东财的板块接口在本机网络下被稳定阻断（`/api/qt/clist/get` 十次零成功），
申万接口有时通有时不通，中证的文件下载被 403。
最后只有新浪的分类接口稳定，于是把它抓下来存成本地 JSON，之后不再联网。

**为什么 akshare 要懒加载？**
`import akshare` 一次要 1.8 秒左右（它得初始化 `py_mini_racer` 才能跑新浪的
JS 加密），如果写死在 `data_fetcher.py` 顶部，这 1.8 秒就发生在主窗口构造函数里，
用户双击图标后要干等两秒才见窗口。
`data_fetcher.py` 里换成了一个 `_懒加载akshare` 代理对象，
`ak.stock_zh_a_spot()` 这种写法完全不用改，但真正的 import 推迟到第一次取数时
—— 那时已经在后台线程里，界面早就出来了。

**柱子上的数字为什么是「自己画的」，而不是用 `setLabelsFormat`？**
这条踩过两次，两次都是同一个接口。

第一次：`QAbstractBarSeries.setLabelsFormat()` 只认 `@value` 这一个占位符，不认 printf。
传 `"%.1f"` 进去不报错，而是**把 `%.1f` 这五个字符原样印在柱子上** ——
屏幕上看着像「百分号错乱」，所以改成 `setLabelsFormat("@value")`。

第二次（就是现在这个）：`@value` 配上 `setLabelsPrecision(小数位)` 之后，
40.16 会被印成 **`4e+1`**、249.65 印成 `2e+2`。原因是
**`labelsPrecision` 的语义是「有效数字位数」，走的是 C 的 `%g`**，
不是小数点后几位。`%.1g` 格式化 40.16 正好就是 `4e+01`。
这个接口没有「固定小数位」的选项，所以只要不自己控制文本，就一定会遇到科学计数法。

最终做法：数字不用 Qt 画，改用 `QGraphicsSimpleTextItem` 自己摆
（`应用/组件/柱状图.py` 的 `_重排标注()`）：

```python
文本 = ("%.*f" % (小数位, 值)) + 单位                      # 完全可控，249.65 → 249.7
项 = QGraphicsSimpleTextItem(文本, 图)                     # 挂在 chart 的图元层上
项.setFont(QFont("Microsoft YaHei UI", 7.5))
# 位置：按 plotArea() 与值轴范围线性插值算，横向图贴在柱子右端，竖向图压在柱顶
图.plotAreaChanged.connect(lambda _区: self._重排标注())    # 缩放、放大、改尺寸都跟得上
```

好处有三个：文本 100% 可控；缩放/放大时跟着重排不跑位；`标注文本()`
这个方法能直接把每个数字的字符串与坐标读出来，验证时不用截图数像素。
实测 13 个板块：`249.7 ｜ 93.8 ｜ 76.4 ｜ 75.2 ｜ 62.6 ｜ 41.9 ｜ 41.8 ｜ 41.2 ｜ 39.3 ｜ 36.6 ｜ 36.6 ｜ 34.4 ｜ 34.0`，
无一处科学计数法。

**正负两色为什么也不能拆成两个 `QBarSet`？**
第一版给「涨」和「跌」各建一个 `QBarSet`（另一个位置填 0），看上去没问题，
但 Qt 会把同一类别里的两个 set **左右各占半个槽位**。自选页实测：
第 1 根柱子画在 x=187..259（中心 223），而类别中心是 186 —— 偏了 37 像素；
再配上自己画的数字，就成了「数字飘在柱子旁边」，越靠右偏得越多（第 4 根偏 59 像素）。
改法跟「逐柱着色」共用一条路：**一根柱子建一个 set 堆叠起来**（其余位置填 0），
颜色按正负给。这样柱心永远落在类别中心，实测第 1 根 x=112..259 中心 185.5，
数字中心 186，完全对齐；柱宽也从 73 像素变成 148 像素，好读多了。

**数字要贴在柱子上，别自己拿 `plotArea()` 插值**
`QBarSeries` 在绘图区里还会再留一圈内缩，用
`区.left() + (i + 0.5) / 个数 * 区.width()` 硬算会和真实柱心差几十像素。
现在优先用图自己的坐标映射 `图.mapToPosition(QPointF(i, v), 系列)`；
但横向图的类别轴在左边、值轴在下面，参数顺序和竖向不同，传错会算到画布外
（实测能算出 `y = -5474`）。所以对结果做了范围校验，落在绘图区外就退回按轴插值。

**为什么不能给单根柱子单独设标签？**
`QBarSet.setLabel(索引, 文本)` 这种重载 PySide6 没暴露，只有单参数的
`setLabel(系列名)`。所以「让某一根柱不显示数字」做不到，只能靠
「只挂有数据的那一组色块」来回避全零柱上的 0；逐柱颜色的堆叠图则统一关掉 Qt 标签、
改用上面的自绘文本。
实测窗口构造从 **2.41 秒降到 0.68 秒**。

**为什么左下角的交易状态是后填的？**
「最近交易日」首次调用要联网取交易日历（约 0.5 秒），而且会顺带触发上面那个
akshare 首次 import。所以侧栏先只显示北京时间，交易日和开闭市状态丢到后台，
拿到再补上。侧栏空半秒，比界面卡半秒好。

**启动画面是必要的吗？**
打好的 exe 从双击到窗口出现，热启动约 1.2 秒、冷启动（第一次读那 369 MB 文件）
约 2.6 秒，这段基本是 PyInstaller 解包 + Qt 加载 dll 的固有成本，改代码省不掉。
所以先亮一块 720×400 的启动画面（`应用/组件/开屏.py`，入口仍是 `main.py` 的
`_开启动画面()`）。实测开屏 **0.26 秒**就上屏。

**开屏动画长什么样？**
一块 720×400 的卡，里面是 44 根**模拟 K 线**逐根长出来（`应用/组件/开屏.py`，
入口仍是 `main.py` 的 `_开启动画面()`）。涨红跌绿、带上下影线，收盘价连成一条淡灰
面积，看着就是一套行情软件的骨架，而不是一张通用厂商 logo 动画。

每根 K 线不是淡入，而是从开盘价「抡」到收盘价 —— `_回弹()` 让它冲到 1.06 再落回 1，
像被一笔大单砸出来；收盘瞬间在端点炸开**九个粒子 + 一圈扩散环 + 一条价格线闪光**，
涨的往上炸、跌的往下炸，方向和 K 线一致。这就是「冲击力」的全部来源，没有靠抖动或
频闪硬凑。

**为什么是 5 秒？**
`_首根延迟` 220 毫秒 + 44 根按 62 毫秒错峰 = 2.9 秒铺满，单根生长 180 毫秒，
粒子寿命 340 毫秒；再加 `收尾()` 的 300 毫秒补满，实测整块画面**约 5.0 秒**消失
（`日志/开屏日志.txt` 的「关闭：共亮 …」是准的，不信帧计数）。

**动画时钟按真实时间走**
原来每帧给 `_时刻` 加 16 毫秒 —— 只要掉一帧，动画就永久慢下去，而且追不回来，
观感就是「越看越拖」。现在整块动画的基准是 `time.monotonic() - 上屏时刻`，
掉帧只会跳过画面，不会拖慢节奏；进度收敛也改成按真实经过时间算，掉帧后收敛速度不变。

**流畅度是怎么保的？**
先说结论：**动画本身一点都不慢，卡的是主线程被冻结包导入抢走了**。这两件事分开测。

渲染路径（把窗口真的显示出来，跑 3 秒，量每一帧）：
| 指标 | 数值 |
|---|---|
| 帧间隔 中位 / 95 分位 / 最大 | 16.0 / 17.6 / 18.7 毫秒 |
| 单帧绘制 中位 / 95 分位 | 2.1 / 3.1 毫秒（60 帧预算 16 毫秒，余量 87%） |
| 窗口掩码的开销 | 0.14 毫秒（有掩码 2.13，无掩码 1.90 —— 不是瓶颈，别为了这个砍圆角） |

为了把单帧压到这个数，做了三件事：
1. **静态层缓存**：卡片底、边框、标题、副标题、版本、网格一帧都不变，一次画进
   `QPixmap`，以后每帧只 `drawPixmap` 一次，不再重复建路径、描边、排字。
2. **几何预计算**：44 根 K 线的坐标、颜色、影线像素长度、出现时刻在 `__init__` 里
   算成扁平的表 `_几何` / `_粒几何`。绘制循环里只剩减法和乘法，没有属性查找、
   没有 `_x()`/`_y()` 调用。离屏单帧绘制从 **2.3 毫秒降到 0.6 毫秒**。
3. **`WA_OpaquePaintEvent`**：整块矩形自己填满，让 Qt 别再擦一遍底。

**剩下的卡顿：GIL 上那块拿不走的原子时间**
`import akshare` 放在工作线程里（冷启动实测 **2598 毫秒**，热启动 587 毫秒），
大部分时间主线程照常 60 帧，但冻结包里的导入是 Python 层的，有一段**几百毫秒的
原子操作一直握着 GIL**，主线程连一个语句都插不进去。

比这更好解决的是另一件事：**建主窗口本身也是一次 0.35 秒的硬阻塞**（首屏要建表格和
图表，实测 327~387 毫秒）。它原来撞在 K 线正在生长的中段 —— 画面正热闹突然定住，
最像「卡顿」。现在 `main.py` 会等 44 根 K 线全画完（最多等 3.2 秒）再去建窗口，
同一段停顿就落在「图已经完整、只有进度条在爬」的时候，看起来就是「正在构建界面」。
实测前后对比：
| 场景 | 停顿分布 |
|---|---|
| 改之前（热启动） | 352 毫秒(918 毫秒处)、62 毫秒 —— **卡在 K 线生长中段** |
| 改之后（热启动） | 360 毫秒(3255 毫秒处)、77 毫秒 —— 卡在 K 线长完之后 |
| 改之后（冷启动） | 532 毫秒(742 毫秒处，导入原子块，不可避免) + 353 毫秒(3253 毫秒处) |

试过、也量过、无效或代价大的路子：
- `sys.setswitchinterval` 从默认 5 毫秒压到 0.5 毫秒：只对「碎片化的多次等待」
  有用，对**原子块**无效（它根本不检查切换标志）。
- 把渲染搬到工作线程：没用，等 GIL 还是等那一整块。
- 后台先起个子进程把模块读进系统缓存：实测热启动仍有 357 毫秒的原子块，不值得多开进程。
- 把导入挪到动画之后：冷启动 2598 + 400 毫秒，开屏得拖到 5.9 秒，违背「5 秒」。

热启动现在整段 K 线动画（0.2~2.9 秒）**一次停顿都没有**，实测
「帧率：278 帧；间隔 中位 16.1 / 95分位 23.0 毫秒」。冷启动还会有一记 0.5 秒的
停顿，来自磁盘冷读那一大坨 pandas/akshare —— 这是 369 MB 冻结包绕不开的成本，
除非把数据层导入挪到开屏之后（代价：表格要多等 2.6 秒才有人喂数据，启动从 5 秒变 8 秒）。

所以现在的取舍是：**把重活尽量往前压**（0.2 秒就开始导），让那几次停顿落在画面
最不值钱的时刻；`收尾()` 再把剩余时间补足到 5 秒。真要一个停顿都没有，只有一条路：
把数据层的导入挪到开屏关闭之后 —— 代价是主窗口的表格要多等 2.6 秒才有人喂数据，
启动总时长从 5 秒变成 8 秒，不划算。

**开屏要「多留一会儿」的道理**
主窗口 1.2 秒就建好了，而 K 线才长到一半，直接收掉等于白做动画。所以 `收尾()` 里有
一条**最短展示**：距开屏上屏不足 `最短展示_毫秒`（现在 **4340**）就先亮着，期间
进度只停在 96%，最后 300 毫秒才补到 100%、再淡出 360 毫秒。热启动实测开屏 0.26 秒
上屏、主窗口 1.3 秒就已在它后面建好、开屏 **4.9 秒**消失；冷启动也不会被提前打断。

嫌慢或嫌快只改一个数：`开屏.最短展示_毫秒`（系统开了「减少动态效果」时用
`最短展示_减少动态_毫秒`，默认 1200）。其余节奏：首根延迟 220 毫秒、相邻 62 毫秒、
生长 180 毫秒、粒子 340 毫秒、冲击环 220 毫秒、淡出 360 毫秒、进度阻尼 0.075、
文字交叉 0.06。停留期间还会换两次话术（「正在打开主窗口」→「马上就好」），
后半段不至于像静止画面。

**开屏为什么不开头淡入了？**
启动那一秒主线程被解包、导 akshare、建窗口挤得断断续续，`windowOpacity` 的动画会被
拖成一条很长的斜坡 —— `日志/开屏日志.txt` 里实测「0.42 秒时透明度 **0.33**」，
屏幕上就是一块半透明、几乎看不清的卡。现在整个开屏**不碰 windowOpacity**：淡入删掉，
淡出也删掉（硬切，主窗口已经在它后面，不刺眼）。

**「动画显示不出来」的真正原因：分层窗口**
前三版的开屏用了 `WA_TranslucentBackground`（圆角卡片要半透明底），在 Windows 上
这就是一条**分层（layered）窗口**，靠 DWM 逐像素合成。这台机器上第二块屏是
`NE153QDM-NY1 1280×800`（虚拟/USB 扩展屏），DWM 对分层窗口的合成没有生效 ——
于是窗口存在、尺寸正确、`PrintWindow` 也能取到内容，**屏幕上却什么都没有**。
肉眼说「看不见」，日志一切正常，上一版还据 PrintWindow 的 94.1% 判定「没问题」，
就是栽在这里。

证据是一条能分辨真假的对照实验（`打包桌面/工具/_抓屏验开屏.py` + `_抓屏对照.py`）：
| 抓法 | 半透明版 | 不透明版 |
|---|---|---|
| BitBlt 抓屏幕·主窗口（普通窗口） | 55.4% 卡片底色 | 55.4% |
| BitBlt 抓屏幕·开屏那块 | **1.3%**（分层窗口 BitBlt 看不见） | **96.3%** |
| 两帧变化 | 11 个采样点 | **1470 个采样点** |

改法是把开屏做成**普通不透明窗口**，圆角改用窗口掩码 `setMask` 切出来 ——
掩码不是透明通道，任何环境都画得出来。改完 BitBlt 直接抓到 96.3%，这才是「屏幕
上真有」的证据。

**落屏规则：永远落在主屏**
试过「跟着鼠标所在那块屏」，结果更糟：鼠标停在虚拟扩展屏上时，开屏就画到用户根本
不看的那块屏上。现在固定主屏正中；`收尾()` 时若主窗口落在别的屏，再把开屏挪过去。
`日志/开屏日志.txt` 里第一行列出**所有屏幕的名字、尺寸、原点**，一眼就能看出是不是
被虚拟屏带偏了。

它不做假进度。`main.py` 每到一个真实阶段才调一次 `推进()`（0.18 加载行情组件 →
0.55 构建界面 → 0.86 恢复界面状态），显示值只朝目标逼近、永不倒退，100% 只留给
`收尾()` 的最后一刻，所以不会出现「卡在 99% 干等」那种最差体验。

**第一版为什么被否了？**
第一版是 560×288，标题 22 像素、柱子着墨只有 11%、阶段文字用次级灰 —— 量出来整块
画面着墨率 2.7%，在显示器上像一张没加载完的空白卡。改成 720×400 后：标题 30 像素、
柱子 44 根 × 8 像素宽 × 96 像素高、着墨 20%~50%、进度条 4 像素加 6 像素滑块、
阶段文字换成主文字色（对比度 17.89:1）；着墨率提到 8.2%，一眼就看得出「它在动」。

字形档位是全项目唯一破例的地方：正文只有 11/12/13/18/22 五档，开屏用 30/16/14/12。
理由是开屏是独立居中画面，不像界面那样要挤表格与层级，照搬同一套档位在 720 像素
宽的画布上会显得又小又空。

**为什么那个 import 不在主线程做？**
`import data_fetcher` 要 0.87 秒（akshare + pandas 首次导入），搁在主线程里开屏会
冻住将近一秒。现在放到工作线程里导，主线程每 8 毫秒泵一次事件循环：实测导入期间
重绘 99 帧，相邻帧间隔中位 10 毫秒、最大 34 毫秒，看不出停顿。
敢放线程是有前提的 —— 实测 `import akshare` 全程一个 `py_mini_racer.MiniRacer`
实例都不会建（V8 要到真正调新浪接口时才初始化），所以碰不到 V8 的线程亲和性；
导入失败会原样抛回主线程，行为与同步写法一致。

**「科技感」怎么不跑偏？**
全项目只有红涨绿跌两种颜色，开屏也守这条：K 线与粒子用涨/跌色，标题、网格、
进度条、面积全是中性色的透明度变化，一个新色相都不加。验证脚本会逐像素查色相 ——
凡饱和度 > 0.35 且亮度足够的像素，只允许落在红（330°~30°）或绿（100°~180°）
区间内，实测越界 **0**。系统开了「减少动态效果」（`SPI_GETCLIENTAREAANIMATION`）
就整套静下来：K 线一次画满、不炸粒子，只保留进度本身。

验收不靠看：`打包桌面/工具/_验开屏.py` 量 **71 项** —— 圆角真切角、进度条宽度与
显示值误差 ≤6 像素（含滑块半径）、阶段文字对比度 17.89:1（深色 15.68:1）、
着墨率 23.1%、色相越界 0、约 2 秒处两帧差 1922 个像素（在动）、减少动态时两帧差
0 个像素、单帧耗时中位 1.2 毫秒、四边不出血。
要「看清楚」的样子用 `_出开屏预览.py` 出二倍渲染大图（`QT_SCALE_FACTOR=2` 让
`grab()` 直接出 1440×800 的清晰像素，不是把 720 的小图拉大）。

**为什么切换模块有淡入？**
`QGraphicsOpacityEffect` + `QPropertyAnimation`，130 毫秒，曲线 `OutCubic`，
不透明度 0.35 → 1.0。关键细节是动画结束必须 `setGraphicsEffect(None)`：
留着这个特效会让整个子树走软件绘制，几千行的表格会明显掉帧。

**热力图为什么是自己画的？**
Qt 没有现成的矩形树图控件。`应用/组件/热力图.py` 里实现了 squarified treemap
（Bruls / Huizing / van Wijk 2000 那套算法），核心是 `_排布()` 和
`_最差长宽比()` —— 每加一块之前先算「加进去之后长宽比会不会变差」，
只会变好就继续加，变差就换一行。实测 129 个板块覆盖率 1.000、
长宽比中位数 1.11、90 分位 1.26、最大 1.92，几乎没有细长条。
面积不直接取成交额，而是开 0.8 次方（`面积指数 = 0.8`）：
沪深两市成交额差着两个数量级，直接用会让小板块缩成一个像素点。
颜色按涨跌幅线性混色，±5% 封顶（`颜色上限 = 5.0`），否则一天里
只有涨停的那几个有颜色、其余全是一片白。

**热力图三个分类为什么各用一层？**
行业取申万二级、概念取新浪概念板块、地域取省份，三者互不重叠。
如果行业和地域都用同一层，同一只股票会在两个聚合里各算一次，
总数就对不上了。

**热力图放大为什么不用改布局、只改高度？**
因为方块本来就按控件尺寸算，只要高度变了、`resizeEvent` 一来自动重排。
但「瞬间变大」看着很硬，所以加了插值：`过渡到高度()` 先存下旧块，
按新高度算出终点块，再按板块名称配对；`paintEvent` 和 `_命中()` 都走
`_显示矩形()`，动画期间返回插值结果、平时直接返回终点。
`resizeEvent` 在动画期间要跳过重排（`if self._进度 < 1.0`），
否则动画自己引起的 resize 会把终点冲掉，方块在半路上「抖」一下。
同理，点击命中也必须用插值后的矩形，不然动画中途鼠标指的位置和看到的对不上。

**成分股为什么显示等权平均涨跌幅？**
板块指数的涨跌幅是按市值加权算的，但这个页面拿的是离线库里的成分股名单，
没有可靠的自由流通市值字段，所以用等权平均 —— 它反映的是「这些股票
今天平均涨了多少」，比加权更直观地回答「我买在板块里随便一只会怎样」。

**为什么表格不再拉伸最后一列？**
`QTableView` 默认 `setStretchLastSection(True)`，最后一列吃掉所有剩余宽度。
11 列的业绩预告表里，「预测指标」「业绩变动」在前面，一旦拉伸，
它们被挤成几十像素的窄条，用户就以为这几列没做。
现在 `数据表._调拉伸()` 会先比总列宽和视口宽度：装得下才拉伸最后一列，
装不下就关掉、让它出现横向滚动条。宁可横向滚，也不能把列压没。

**列宽为什么不用「中文字 12px、英文字 7px」估算？**
低估了 6~10px，「股票简称」这种列会差三四个字，正好把简称截断。
现在 `_估算列宽()` 用 `QFontMetrics.horizontalAdvance()` 逐列量真宽度，
表头额外留 18px 给排序箭头，上限放宽到 420px，量完再乘 1.04 兜余量。

**情绪概览为什么先摆六张空卡？**
涨停/跌停家数要联网统计，冷启动要三四秒。原来这几秒页面上只有一行
「正在统计当日情绪数据…」，用户会以为这个页面坏了（这就是当初反馈的
「情绪概览没刷新出来」）。现在 `加载指标(骨架=[...])` 先把六张卡画出来、
值填「—」，数据回来再逐张 `换值()`，观感上就是「在刷新」。

**离线库里的总市值单位？**
新浪分类接口给的是**万元**（创达新材 226416.09 万 = 22.64 亿）。
`fetch_sector._板块库成分()` 里统一乘 10000 转成元再去格式化，
不转的话表格会显示成「22.64 万」，差一万倍。

**怎么确认按钮文字没被裁掉？**
不能靠眼睛看（尤其缩放 125% 的时候）。工具目录下的 `工具/_查错位.py`
在 offscreen 模式下把窗口按 1120×720 / 1440×920 / 1920×1080 三种尺寸各建一遍，
十个模块逐个打开，检查七类问题：

| 检查项 | 判据 |
|---|---|
| 按钮横向被裁 | 控件宽 < `sizeHint().width()` |
| 按钮纵向被裁 | 控件高 < `sizeHint().height()` |
| 单行文字放不下 | 标签宽 < `QFontMetrics.horizontalAdvance(文字)` |
| 换行文字行数不够 | 标签高 < `heightForWidth(实际宽)` |
| 下拉框文字被截 | 宽 < 当前项文字宽 + 42（留给箭头和内边距） |
| 控件真重叠 | 兄弟控件 `QRect.intersected` 面积 > 1×1 |
| 溢出父容器 | `x + width > parent.width()` |

这套检查当初抓到 11 处同一个问题：侧栏四个主题按钮挤在一行，
每个只分到 54px，而「随时间变化」需要 65px，五个字被切掉一截。
改成 2×2 网格 + 每个按钮 `setMinimumWidth(sizeHint().width())` 后归零。

**K 线为什么改用数值轴？**
第一版用 `QBarCategoryAxis`（把「第几根」当类别），做滚轮缩放时要么每次切片重建
（300 根一次 175 毫秒，拖动只有 5 帧），要么就得改类别轴。问题在于
`QBarCategoryAxis.append()` **会去重、还会丢掉空串**：为了让每根蜡烛都有类别，
老代码往未选中位置填空串，结果 300 个空串只剩 1 个类别，蜡烛全挤在十来个位置 ——
K 线图一直是错的，只是平时不放大看不出来。换成零宽字符 `​` 也只保住 289 个。

改成 `QValueAxis` 后两个问题一起消失：既可以一次性把全量数据灌进 series、
缩放平移时只改 `setRange`（9 毫秒一次），也不必再编造类别标签。
`QCandlestickSeries` 和 `QBarSeries` 挂数值轴画出来和挂类别轴完全一样
（实测有柱列数、x 范围、十等分分布都对得上），所以不用自己画蜡烛。

代价是数值轴不会自动标日期，日期得在 `paintEvent` 里手绘。
手绘时有个坑：**`QChart.mapToPosition(点, 系列)` 的系列必须属于那个 chart**，
把主图的蜡烛系列丢给 MACD 图去换算是算不对的（刻度会全叠在左端）。
正确做法是拿主图算比例，再按两张图绘图区宽度的比映射过去。
现在跑一遍是「累计检查按钮 144 次、标签 420 次、控件 1118 次，没有问题」。

**均线颜色为什么曾经全是黑的？**
老代码写的是 `for 窗口, 颜色 in zip(self._均线窗口, config.均线颜色)`。
`config.均线颜色` 是**字典** `{5: "#d18700", 10: "#2f6fd0", ...}`，`zip` 迭代出来的是**键**，
于是 `[(5, 5), (10, 10), (20, 20)]` —— `QColor(5)` 被当成 QRgb 整数，
实测 `MA5 #000005 / MA10 #00000a / MA20 #000014`，三根均线全是近黑色，
混在蜡烛图里根本看不出是均线。改成 `config.均线颜色.get(int(窗口), "#666666")` 才对。
**教训：对字典做 `zip` 之前先问一句「我要的是键还是值」。**

**副图为什么能开关还不用重建整个组件？**
`K线图.设显示(均线窗口=…, 显示MACD=…, 显示KDJ=…)` 只改这三个成员，
传 `None` 表示这项不动。要关掉的副图先 `setParent(None)` + `deleteLater()` 再让
`_建图()` 重新建，因为 `QChart` 一旦挂到视图上就没法退回去，重建比拆装干净。
日期归属也跟着变：只画在**最下面那张**图上，否则会压到下一张的顶部。

**折线图的十字线怎么画的？鼠标事件为什么要投给 viewport？**
十字线不是 `paintEvent` 手绘的，而是一条 `QLineSeries`（虚线的 `QPen`），
平时 `setVisible(False)`，鼠标移动时用 `replace([两点])` 把它拉到当前类别序号上 ——
这样它自己会跟着坐标轴缩放，放大后位置也准，不用重算像素。
真正容易踩的是事件：**Qt 把鼠标事件投给 `QChartView` 的 viewport 子控件**，
只重写视图自己的 `mouseMoveEvent` 收不到。所以有个 `_悬停视图(QChartView)`
把 `mouseMoveEvent` / `leaveEvent` 转成回调（`到移动` / `到离开`）。
验证时同理：必须 `应用.sendEvent(视图.viewport(), QMouseEvent(...))`，
发给视图自己是不触发的 —— 第一轮验证「十字没出现、读数是空的」就是这个原因。

**放大收回为什么必须记「最内层图」的高度？**
`图块` 放大时要先记住原高度，收回去用。第一版记的是 `self._图.height()`，
而页面上传进来的是 `可刷新折线` 这个**外壳** —— 它比里面的 `折线图` 多一行
来源说明，292 而图本身只有 270。于是「270 → 放大 → 收回」变成 292，越收越高，
多点几次就回不去了。改法是在 `_目标图()` 里顺着 `.图` 属性一路剥到最里面
（`可刷新折线` → `折线图`），记高度和设高度都用它。复测十三个图块，
`收回` 值与 `初始` 值全部相等。

## 七、常见问题

**双击没反应？**
先看 `日志\异常.txt`（源码运行时是项目目录下的 `日志\`）。
九成是缺库，命令行执行 `python 运行.py` 会给出中文提示。

**打成 exe 后新浪系接口全空，源码却正常？**
这是 `sys.stdout` 为 `None` 导致的，见第八节第一条。

**界面字体发虚？**
Windows 缩放不是 100% 时，Qt 的高分屏缩放可能和系统设置打架。
在 `main.py` 里把 `QFont("Microsoft YaHei UI", 9)` 的字号调大一号试试。

**板块点进去是空的？**
`数据` 目录里的离线库不全。先跑 `build_sector.py` 重建。

**北向资金历史全是空？**
2024 年 8 月之后官方停止披露日度明细，只能看到概览，这是数据源的问题。

**表格里的红色绿色反了吗？**
国内习惯红涨绿跌，本软件就是这个配色。如果系统是深色模式而表格是浅色，
那是 Qt 表格用 canvas 绘制的限制，不影响数据。

**能不能不装 Python，直接给我一个 exe？**
可以，用 PyInstaller 打包成 onedir 模式的文件夹版。见第八节。

**点右上角的 ✕ 没反应？**
正常，它先弹确认框。按「退出」才真退，按「继续使用」或 Esc 就留下。
自检模式（`--自检=`）会把这个确认框关掉，否则无人值守时会挂死进程。

**对话框里的按钮是英文的？**
打包时漏了 Qt 的中文翻译包。检查 exe 同级 `_internal\PySide6\translations\qtbase_zh_CN.qm`
在不在，不在就往 spec 的 `datas` 里补，见第五节。

## 八、打包成独立 exe

已经打好了：`A股全景看板桌面版_软件版` 那个文件夹里就是，解压即用，目标机器不用装 Python。

想自己重打，用项目里的 spec 文件（源码开发者参考）：

```bat
cd C:\ds\打包桌面
python -m PyInstaller --noconfirm --clean A股全景看板.spec
python 整理发布.py
```

`整理发布.py` 会把 12 个离线库复制到 exe 同级的 `数据\`，再写一份使用说明。

这个 spec 里有四个地方是踩过坑才写进去的，改打包配置时别删：

**一、`console=False` 会让 `sys.stdout` 变成 `None`。**
PyInstaller 的 windowed 模式没有控制台，`sys.stdout` / `sys.stderr` 直接是 `None`。
akshare 内部的进度条会往 stdout 写，一旦是 None 就抛
`AttributeError: 'NoneType' object has no attribute 'write'`。
症状极具迷惑性：**源码运行一切正常，打成 exe 后新浪系接口全部取不到数**（重点关注指数、全市场快照、个股日线都挂），
而东财、统计局那些不打印进度的接口又是好的。
解决办法在 `main.py` 最前面——检测到 None 就挂一个 devnull 流上去。

**二、`collect_submodules` 认 `sys.path`，不认 Analysis 的 `pathex`。**
十个页面模块是 `importlib.import_module` 动态加载的，静态分析看不到。
在项目目录里跑 `collect_submodules('应用')` 能收到 22 个模块，
但在打包目录 `C:\ds\打包桌面` 里跑只能收到 0 个——于是打出来的 exe 报
`ModuleNotFoundError: No module named '应用.页面'`，而且打包过程一句警告都没有。
所以 spec 里先 `sys.path.insert(0, 项目)`，再收，最后还加了一个断言：
收不到页面模块就直接中止打包。

**三、`py_mini_racer` 的 native dll 必须一起带。**
它是 akshare 跑 JS 解密用的，漏了不报错，只是相关接口静默失败。
用 `collect_all('py_mini_racer')` 整包带走，`akshare` 同理（它自带映射表文件）。

**四、用 onedir 不要用 onefile。**
单文件每次启动要把三百多兆解压到临时目录，实测 30 秒以上；文件夹模式 2.7 秒。

打完之后别只看窗口能不能开，要验证 exe 里**能不能真取到数**：

```bat
A股全景看板.exe --诊断=C:\temp\诊断.txt
A股全景看板.exe --自检=C:\temp\自检.txt
```

`--诊断` 只测七个代表性接口，十秒出结果，适合排查网络；
`--自检` 把十个模块挨个打开一遍，记录每页几行数据，约 45 秒。
两个都是跑完自己退出，不看界面，所以能在没有人的环境里跑。
